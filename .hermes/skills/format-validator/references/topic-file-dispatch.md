# Topic File Dispatch — Format Validator

> How the validator routes `wiki/topic/*.md` files correctly.

## Problem

Topic files (`wiki/topic/<slug>.md`) have this frontmatter:

```yaml
type: index
scope: topic
topic: <slug>
auto_generated: true
last_updated: YYYY-MM-DD
```

They have `type: index` but NO `level` field. If dispatched to `validate_index()`, the missing `level` triggers 100+ false ERRORs.

## Root cause

Per `index-spec.md` §5.1:

> `wiki/topic/<topic>.md` is auto-generated by Index Agent but is NOT an index in the navigation sense. Topic files aggregate sources sharing the same topic slug, linking directly to source files without going through a parent index. They function as content side-channels.

Topic files have their own format (defined in Index Agent skill), separate from the index-spec.md hierarchy.

## Correct dispatch

```python
file_type = fm_parsed.get('type', 'MISSING')
file_scope = fm_parsed.get('scope', '')

# Topic files: if scope=topic OR file is in wiki/topic/, treat as topic
if file_scope == 'topic' or str(filepath.parent.relative_to(KB)) == 'wiki/topic':
    issues = validate_topic(filepath, fm_parsed, raw_fm)
elif file_type == 'concept':
    issues = validate_concept(...)
elif file_type == 'source':
    issues = validate_source(...)
elif file_type == 'index':
    issues = validate_index(...)
```

## Light topic validation

Topic files only need light validation:
- `topic` field present and matches filename
- `auto_generated: true`
- `last_updated` valid ISO date
- H1 title present

Do NOT check for `level` field, `parent` wikilinks, or index-style sections.

## Files to skip entirely

| File | Reason |
|---|---|
| `context/USER.md` | Julius's profile, read-only, no frontmatter expected |
| `context/context.md` | If it has frontmatter, validate normally (has `type: index`) |
